# Ecosystem deployment and operation

Status: NOT production_ready. Axora-only code is implemented; remote integrations need real acceptance. Do not deploy as a complete live ecosystem until the gates below pass.

Use .env.example for existing Supabase/SMTP settings and new server-only variables. AXORA_FACTORY_URL / AXORA_FACTORY_ADMIN_TOKEN connect Factory. AXORA_DASHBOARD_URL / AXORA_DASHBOARD_SERVICE_TOKEN connect the future dashboard API; AXORA_DASHBOARD_BILLING_TOKEN authenticates its billing reads back to Axora. AXORA_ECOSYSTEM_JOB_SECRET protects the scheduler route. AXORA_PAYMENT_API_URL / AXORA_PAYMENT_API_TOKEN / AXORA_PAYMENT_MERCHANT_ID / AXORA_PAYMENT_WEBHOOK_SECRET configure the custom payment bridge. Use independent high-entropy secrets of at least 32 characters. Never expose these using NEXT_PUBLIC_ variables, browser configuration or logs. No Google private key is needed in Axora: credentials and CRUD belong in the separate server adapter.

Keep AXORA_INTEGRATION_LOCAL_TEST=0 in production. AXORA_DIST_DIR is optional QA build isolation, normally unset. HTTPS base URLs must have no embedded credentials, query or fragment. Tokens must agree with their respective remote service, not with a public browser key.

After staged migration and contract acceptance: npm ci, npm run typecheck, npm run lint, npm run test:ecosystem, npm run test:ecosystem:e2e, npm run build. Browser QA uses synthetic credentials, local fixture services and a separate build directory; install a supported Chrome browser for that check. npm run ecosystem:worker -- --once processes a tick; omit --once for a long-running worker, or schedule authenticated POST /api/jobs/ecosystem. Do not run these against production until explicitly approved. Each tick handles one durable task, including polls and health checks; monitor backlog and choose capacity accordingly.

Register an actual existing order in /admin/ecosystem, review real requirements/modules, submit to Factory, and inspect missing questions/options. Prepare the site/Sheets without customer access, then generate only when the verified template/options and prerequisites allow it. Approve/confirm delivery only after real Factory QA/preview/admin requirements pass. Observe immutable trial start and actual dashboard invite/access receipt. Create a pending hosted invoice and verify signed provider lookup/settlement; never use legacy manual one-time order confirmation for subscriptions.

Monitor blocked/failed jobs, max-five attempts, lease expiry, provider lookup failures, last health/sync observations and pending suspension receipts. Do not automatically restart exhausted work with new keys; investigate and reconcile remote state. Status configuration is not proof of connectivity. Keep access-policy suspension disabled until remote enforcement is tested; no automatic deletion exists.

Remaining gates: dashboard service API implementation (outside authorized scope), actual Factory deployment/AI/preview acceptance, real Sheets CRUD and website revalidation, real customer identity linking, payment provider/bridge onboarding and reconciliation/refunds, staging Supabase RLS, production scheduling/monitoring and larger-scale pagination. Rotate credentials using staged remote/local updates and audit only identifiers/statuses, not secret payloads.
